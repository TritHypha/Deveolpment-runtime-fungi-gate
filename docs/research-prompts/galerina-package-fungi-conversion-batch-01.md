## Why these are dossiers rather than translations

The current readiness inventory labels these packages convertible from their
TypeScript dependency shape, but that label does not prove executable `.fungi`
coverage. The dossiers must expose every missing language, GIR, effect,
runtime and SLIDE host contract before implementation begins.

The first implementation tranche should start with the smallest dependency
foundations only after the coordinating branch records:

- frozen canonical values and calling convention;
- exact K3 decision and `_=>` exit encoding;
- admitted effect/capability schema;
- flow-owned value lifetime and erasure rules;
- bounded package import/manifest ABI;
- executable `.fungi` oracle and differential harness;
- mutation and security-refusal test requirements.

`galerina-tri-regex` and `galerina-ext-tritsocket` are intentionally later in
the batch. They are valuable independent-project exemplars, but their K3,
budget and ABI surfaces make premature mechanical translation unsafe.

## Completion evidence

Batch preparation is complete only when all eight named dossiers:

- cite current file/line and generated graph evidence;
- distinguish verified behavior from design;
- contain dependency, lifetime, K3/exit and attack-surface maps;
- define differential and mutation preservation matrices;
- list exact SLIDE blockers without silently inventing them;
- identify any defensible paper/falsification opportunity.

No dossier or quarantined candidate changes package completion percentages.
Only executed, independently verified and admitted `.fungi` behavior can do
that.
