# R&D reconciliation, VPEG evidence, and Fungi repair design

Date: 2026-07-31

Status: owner-approved design

Scope: Galerina, independent SLIDE, the Knowledge Base, and the external
`Galerina-Fungi-Package-Staging` quarantine

## Outcome

This chapter produces one evidence-consistent live record before independent
review, a numbered primary-source R&D corpus with checked maths and
zero-trust scores, two bounded independent-review prompts, and a test-backed
resolution of every currently flagged `.fungi` syntax or logic issue.

VPEG, the Deterministic Shape Fabric, and the Neural Shape Engine remain real
planned SLIDE components. Their authority boundary is:

```text
untrusted shape/model proposal
  -> bounded candidate set
  -> exact content and transitive-identity re-derivation
  -> independent deterministic reconstruction
  -> complete validator and policy admission
  -> K3 ALLOW | DENY | INDETERMINATE
  -> only exact ALLOW may execute
```

The deterministic fabric may reuse a verified immutable fragment. The neural
engine may rank or propose candidates. Neither a cache hit, graph location,
topological similarity, model confidence, hardware presence, nor prior
success can authorize execution.

## Current implementation boundary

The live SLIDE repository currently implements a closed V2 contract, a
reference frontend, V2-D/V2-E validators, a prepared executor, mutation
evidence, and a bounded benchmark. It does not yet implement a production
VPEG, a production native backend, or an executable Neural Shape Engine.

The live Galerina repository treats `.fungi` compiler stages as authoritative
specifications while TypeScript remains the executing bootstrap and
differential layer. A syntax-clean staged `.fungi` file is not an executed
replacement and cannot retire its TypeScript oracle.

These facts are the baseline that TODOs, roadmaps, reports, prompts, diagrams,
and scores must preserve.

## Research records

New research receives collision-free Knowledge Base identifiers beginning
after the existing RD-0600 defensive-paper reservation. Each RD record must
contain:

- a precise question and trust boundary;
- current repository facts separated from proposals;
- primary standards, specifications, papers, and vendor/kernel documentation;
- alternatives, including build nothing;
- explicit equations, units, assumptions, worked examples, and falsification
  thresholds;
- the Tri -1/K3 contribution and limits;
- authority, injection, provenance, memory, resource, durability, portability,
  and developer-experience consequences;
- a smallest safe experiment and rollback path;
- the ten-dimension zero-trust score with hard-veto check; and
- an assessed scientific-paper decision under `docs/paper/README.md`.

An unknown dimension remains `PENDING`. Research may authorize an experiment;
it cannot label an unbuilt mechanism production-ready.

## Research programme

The initial programme covers eight separable decisions:

1. content-bound execution versus linked runtime and pathname loading;
2. detached GIR as the sole backend input plus a second frontend/profile;
3. VPEG exact reuse against full rebuild and ordinary action-cache controls;
4. Neural Shape Engine proposal/ranking with poisoning and determinism tests;
5. encrypted immutable shape/memory indexes and injection-resistant reads;
6. cross-platform durable immutable generations and recovery;
7. digest-suite agility and long-horizon identity;
8. signed offline hardware/driver manifests with present-but-unusable states.

VPEG experiments compare at least:

```text
B0 = full deterministic rebuild
B1 = ordinary exact action cache
B2 = exact VPEG fragment reuse + complete validation
B3 = structural/neural retrieval + full deterministic reconstruction
```

No speedup is publishable unless all lanes execute an equivalent admitted
workload and produce the same exact result identity. Report setup, lookup,
validation, reconstruction, execution, failure, storage, and invalidation
costs separately.

## Independent-review prompts

Two prompts are required:

- **project-aware:** read-only repository access, exact paths, commands,
  current implementation claims, and a fixed report destination;
- **no-repository:** a self-contained evidence pack with no implied access to
  local files or private material.

Both require primary sources, shown maths, assumptions and units, explicit
alternatives, adversarial tests, contradiction reporting, a dimension-by-
dimension zero-trust score, paper-worthiness review, and any valuable finding
outside the supplied questions. Review output is advisory and cannot edit,
sign, commit, push, rotate keys, or grant authority.

## `.fungi` repair boundary

Every live entry in `TRANSLATION-ISSUES-LOG.md` is classified as:

- reproduced defect;
- stale and retracted with fresh evidence;
- intended language rule with improved diagnostics/documentation;
- missing candidate dossier/parity evidence; or
- owner-only product decision.

For a reproduced compiler, checker, CLI, or audit defect, first add a focused
test that fails for the expected reason. Implement only the smallest fix, run
the focused test, then the package and repository gates. For candidate-source
logic, write parity and hostile vectors before changing the implementation.

The source style remains:

- `if` only for a Boolean decision;
- `check` for typed K3 where only `ALLOW` proceeds;
- exhaustive `match` for alternatives;
- explicit terminal exits for unknown, miss, malformed, exhausted, and
  invariant-failure states;
- flow-owned values and deterministic cleanup;
- no raw pointers, manual free, ambient authority, hidden sidecar, nested
  dependency tree, or invented syntax.

Developer ergonomics is a security property. A deliberately unsupported
construct should receive one clear diagnostic with an actionable admitted
form. A senior developer should not need to infer that a successful command
checked nothing, that a parser accepted a construct the resolver cannot bind,
or that a safe access miss may silently disappear.

## Diagram rule

The final SLIDE SVG may show implemented and measured components in green,
implemented non-authorizing experiments in amber, planned/unbuilt work in
blue, and prohibited authority paths in red. The Neural Shape Engine cannot be
shown as built until executable proposal generation, poisoning controls,
deterministic replay, complete downstream validation, and measured comparison
evidence exist.
